# Job SMS stage one implementation plan

Approved scope: add connected-account SMS sending alongside unchanged manual SMS/email. Default off; administrator-controlled enablement. No inbound capture or email changes.

1. Test duplicate attempt claims, validation, uncertain outcomes and provider status reconciliation before implementing.
2. Add dedicated job_sms_messages table and an explicit additive migration. Existing canonical jobs and manual logs retain ownership. Store authenticated actor, sender snapshot, immutable content, request fingerprint and provider ID.
3. Add authenticated job SMS routes: canonical job access/contact verification, connected SMS sender validation, atomic claim before dispatch, no fallback devices or automatic resend, status-only reconciliation. Add independent admin-only feature setting.
4. Add isolated composer component using existing templates; persist attempt reference before submission and recover after refresh. Preserve manual links and integrate new records in existing timeline.
5. Validate route/service failure paths, composer interactions, campaign regression suite, TypeScript and production build. Review diff and apply additive migration with feature disabled. Commit and push only the intended files.

Acceptance: test phone receives exact edited template/blank message from selected sender; record survives refresh; duplicate requests submit once; missing contact/disconnected sender blocked; unknown outcomes never auto-resend; administrator can disable new sending without hiding history; manual SMS/email remain usable. Live customer sends are excluded from automated verification.
